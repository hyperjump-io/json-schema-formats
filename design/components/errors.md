# Errors

Each `assert` function throws an error of its own class, like
`InvalidDateError`, so a caller can tell formats apart with `instanceof`.
Each class extends `Error`, and has:

| Property | Description |
| --- | --- |
| `value` | The value that isn't valid |
| `reason` | What's wrong, as a code |
| `part` | The part of `value` that's wrong, like `"month"` |
| `start`, `end` | The span of the problem, as `value.slice(start, end)` |

`start` and `end` are UTF-16 indexes, like every index of a JavaScript
string and positions in the Language Server Protocol. Something that's
missing is an empty span where it would go.

The classes share a base class, `FormatError` in `src/diagnose.js`, that
sets the properties and the message. It isn't exported or declared. A
base class can be exported later without breaking anything, if a caller
needs to catch every format's error with one `instanceof`.

The constructors are private in the declarations, so throwing them isn't
part of the API.

## Reasons and parts

`reason` is one of a shared list of codes, and each class's `reason` is a
union of the ones it can have, like `InvalidDateError`'s
`"invalid-character" | "invalid-value" | "missing" | "nonexistent-date"`.
A `switch` on it is checked by TypeScript. `part` is a union of the
format's parts, like `"year" | "month" | "day"`.

| Reason | Span |
| --- | --- |
| `invalid-character` | The character |
| `invalid-value` | The part, which has the right characters but isn't a value it can be, like a month of `13` |
| `missing` | Empty, where the part would be |
| `too-long` | The characters past the limit |
| `invalid-order` | A duration's unit that's out of order |
| `invalid-escape` | A JSON Pointer's `~`, or an `sf-string`'s `\`, and the character after it |
| `invalid-percent-encoding` | A `%` and up to two characters after it |
| `nonexistent-date` | The day |
| `nonexistent-leap-second` | The second |
| `wrong-day-name` | An HTTP date's day name |
| `invalid-idn` | The whole hostname |
| `invalid-syntax` | The whole regular expression |

`src/assert.test.js` checks that every reason and part an error declares
comes up, so the unions don't list what can't happen (see
[Diagnosing](diagnosing.md#checked-by-differential-testing)).

## Messages

A message names the format and the value, then says what's wrong and
where it starts, then a hint if there's one, like `@hyperjump/uri`'s:

```text
InvalidDateError: Invalid date: 2020/01/01 — "/" isn't allowed after the year, at 4; it must be "-"
InvalidEmailError: Invalid email: é@c.com — "é" isn't allowed in the local part, at 0; it's allowed in an idn-email
```

The position comes before the hint, which ends the message because it
says what to do. A character that can't be seen, like a control
character or a space other than U+0020, is written as its code point,
like `U+00A0`. A problem that `idn-hostname` or the engine reports has
their words and no position, since they don't say where.

## Numbers

The errors of the number formats, like `InvalidInt8Error`, have `value`,
which is the number, and `reason`, and no `part`, `start`, or `end`. A
number is one value, so there's no part of it to point at. They're
declared with their own properties in `src/index.d.ts`, and the message
has no position:

```text
InvalidInt8Error: Invalid int8: 300 — it must be -128 to 127
```

Their reasons are `not-an-integer`, `out-of-range`, and `too-precise`
(see [OpenAPI formats](openapi-formats.md#errors)).

## URIs and IRIs

The URI and IRI functions throw `@hyperjump/uri`'s `InvalidUriError` and
`InvalidIriError`, which have `rule` and `component` in place of `part`.
The package exports them, so a caller can catch them without importing
`@hyperjump/uri`.

## Rejected

- **One `InvalidFormatError`**, with the format as a property, the way
  `@hyperjump/uri` has `rule`. A caller couldn't narrow `reason` and
  `part` to a format's with `instanceof`.
- **Wrapping `@hyperjump/uri`'s errors** in classes of this package. They
  already say what's wrong and where, and a wrapper would be a second
  class for the same error.
- **Generated API docs.** 1.1.0 had a site generated by `typedoc`. The
  `.d.ts` files' JSDoc is what editors show, and the user docs are in
  `website/`, like every Hyperjump package's.
